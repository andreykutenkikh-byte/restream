# Мониторинг маршрута

Основная панель `/` показывает TCP-задержку от фиксированного сервера приёма до
каждого добавленного сервера. Это время установки TCP-соединения, не ICMP ping.
Во время межсерверной передачи отдельно доступны RTT SRT, полезный битрейт,
трафик с повторами, повторно отправленные и отброшенные отправителем пакеты.
Последние два счётчика показаны за указанный интервал, не за весь эфир.
Повторы не равны окончательным потерям; отбрасывания получателем и результат
воспроизведения на YouTube этими измерениями не подтверждаются.

Измерения TCP устаревают через 45 с, SRT и вход — через 10 с. Смена соединения,
сброс счётчика и первая выборка дают «Нет данных» для скорости/дельт. Локальный
маршрут через сам приёмник не имеет межсерверного участка. История доступна
по прежней ссылке «История качества и диагностика», без ключей и исходных URL.

До эфира можно выбрать сервер при остановленной отправке. Если OBS уже
выключен, но отправка осталась включённой в панели, кнопка «Выбрать до
следующего эфира» сначала останавливает её штатным механизмом и дожидается
подтверждения. Выбор не начинает следующий эфир и не меняет адрес OBS.

Проверка скорости использует одноразовый токен в зашифрованных планах агентов.
Она работает 3 с, ограничена 64 Мбит/с и 24 МБ; это измерение в указанных пределах,
не максимальная пропускная способность. Во время входящего видео, отправки,
прогрева или переключения проверка запрещена. Агенты прекращают её, если
появляется видео. У серверов должен быть явно настроен отдельный TCP-порт
`network_probe_port`; занятый порт не заменяется. Установка этого компонента
допустима только без OBS-потока и без изменений соседних приложений.

## Пропуски OBS

Сервер RTMP не получает точного счётчика потерь IP-пакетов от OBS. Для показателя
пропущенных кадров нужен локальный помощник. Он читает только `GetOutputList`
и `GetOutputStatus` OBS WebSocket v5; не запускает/останавливает поток и не
получает ключи отправки. Aitum Vertical выбирается отдельным именем выхода.

1. В OBS включите WebSocket, задайте пароль и оставьте доступ только с компьютера.
2. В панели нажмите «Подключить статистику OBS», получите конфигурацию для
   нужного источника. Токен позволяет только отправлять числовую статистику
   этого источника. Сохраните файл локально, не публикуйте его.
3. В окружении Python проекта узнайте имя вертикального выхода:
   `python -m scripts.obs_network_monitor --list-outputs`.
4. Запишите это имя в поле панели и скачайте конфигурацию, затем запустите
   `python -m scripts.obs_network_monitor --config obs-monitor.json`.
   Пароль WebSocket вводится скрыто и не сохраняется в конфигурации.
5. По кнопке «Отключить статистику OBS» токен отзывается. При остановке помощника
   значения устаревают, не превращаясь в нулевые потери.

`outputSkippedFrames` — пропуски выхода OBS, не число IP-пакетов. Значения основной
трансляции OBS не подходят для отдельного выхода Aitum. Поэтому помощник не
выбирает автоматически основной активный поток.
